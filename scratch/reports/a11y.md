# Accessibility (a11y) Review Report

**Date:** July 31, 2026
**Scope:** `src/components/` and `src/layouts/`

## 1. Strengths (Good Practices Implemented)

*   **Semantic HTML:** Excellent use of structural landmarks across the site (`<header>`, `<footer>`, `<main id="main-content">`, `<article>`, `<aside>`, `<nav>`).
*   **Skip Links:** Implemented correctly in `BlogPost.astro` and `SecretMenu.astro` (`<a href="#main-content" class="sr-only skip-link">`).
*   **Focus Management:** The mobile hamburger menu (`Header.astro`) and the CCPA Do Not Sell modal (`Footer.astro`) correctly implement keyboard focus traps, preventing users from tabbing outside the active modal/menu.
*   **ARIA Landmarks & Roles:**
    *   Proper `aria-label` usage on navigation elements (Main navigation, Footer navigation, Site directory, Table of Contents, Breadcrumbs).
    *   The CCPA modal correctly uses `role="dialog"`, `aria-modal="true"`, and `aria-labelledby`.
    *   `aria-hidden="true"` is correctly used on decorative separators (e.g., in breadcrumbs and footer).
    *   The Cookie Banner correctly uses `role="region"` and `aria-live="polite"`.

## 2. Areas for Improvement (Deficiencies & Fixes)

### A. ARIA Roles & State
*   **Active Link State (`HeaderLink.astro`):**
    *   *Issue:* The component adds an `.active` CSS class when a link matches the current path, but fails to apply `aria-current="page"`.
    *   *Fix:* Add `aria-current={isActive ? 'page' : undefined}` to the `<a>` tag.
*   **Dynamic Announcements (`NewsletterCTA.astro`):**
    *   *Issue:* Form submission outcomes (success/error) are injected into `<p id="newsletter-message">`. Screen readers will not announce this update automatically.
    *   *Fix:* Add `aria-live="polite"` or `aria-live="assertive"` to the `#newsletter-message` element.

### B. Image Alt Text
*   **Hero Images (`BlogPost.astro`, `SecretMenu.astro`):**
    *   *Issue:* Hero images currently use the article `title` as their `alt` text (`alt={title}`). While this prevents empty alt errors, it is often redundant or not descriptive enough for visually impaired users.
    *   *Fix:* Consider adding a dedicated `imageAlt` field to the markdown frontmatter for more descriptive alternative text.

### C. Color Contrast Risks
*   **Annoyance Score (`SecretMenu.astro`):**
    *   *Issue:* The dynamic text colors for high annoyance scores (Yellow: `#F59E0B`, Red: `#EF4444`) are displayed against a dark background (`#1E293B`). The Yellow `#F59E0B` against `#1E293B` might fail the strict WCAG AA 4.5:1 contrast ratio for normal text.
    *   *Fix:* Lighten the yellow/red hex values slightly or check them with a contrast analyzer tool.
*   **YMYL Disclaimer (`YMYLDisclaimer.astro`):**
    *   *Issue:* Uses colored text (e.g., `#fca5a5`, `#fcd34d`) on tinted backgrounds (e.g., `rgba(239, 68, 68, 0.1)`). These need to be validated to ensure they meet the 4.5:1 contrast ratio requirement.
